## 1. What is wrong, and why it is a prompt of its own

`ComputeTargets/tests/wkb_reference_data.json` holds the campaign references for `tau`, `cs_tau`,
`friction_F`, `rho_G` and `rho_T` on three models. Its own `method` string, for `QCDModel`, ends:

> *"H(z) here is itself a spline evaluation of T(z), so no higher-precision reference exists."*

So **every QCD reference in that file is built from the shipped `T(z)`**. Prompts 04, 05, 06 and 07
each move `T(z)` or the break-point set, each therefore moves every QCD reference by up to
~3.5e-08 relative, and **ten test modules assert against those references** — the `grep` is in §2
item 3.

If each of those prompts has to discover that for itself, four agents will each re-derive the same
map, and at least one will paper over a failure by loosening a tolerance. This prompt does the
discovery once, makes regeneration a single command, and **proves the command reproduces the
shipped file bit for bit before anything moves**. It changes no number.

## 2. What to build

1. **`docs/qcd-background-audit/generate_qcd_references.py`.** Take
   `docs/gktk-remedial/generate_references.py` as the starting point and reduce it to what this
   campaign needs: regenerate **the `QCDModel` block only**, in the JSON's existing schema, leaving
   `RadiationModel` and `LambdaCDMModel` untouched byte for byte. It must:
   - write to `ComputeTargets/tests/wkb_reference_data.json` **in place**, preserving key order and
     formatting, so that a regeneration diff shows only the numbers that moved;
   - update that block's `generated`, `generator` and `method` strings, and **append** — never
     replace — a provenance note saying which campaign prompt regenerated it and at what
     `T_Z_REPRESENTATION_VERSION`;
   - support `--dry-run`, which prints the diff it *would* make and exits non-zero if anything
     would change. **That is the acceptance test for this prompt**: on this tree, `--dry-run` must
     report **no change**.
   - carry its own docstring saying what the reference is, what it is *not* (on this tree it is
     circular — built from the object it scores), and that prompt 06 makes it non-circular.
   - need no Ray and no datastore. State the wall time in the log.

   If the existing generator cannot be reduced without rewriting it, say so as a
   `STRUCTURALLY REQUIRED` deviation and write a fresh script against the documented schema; do not
   edit the original in place.

2. **Reproduce the shipped file exactly.** Run the generator with `--dry-run`. If the QCD block
   does not reproduce, **stop and report** with the largest discrepancy and its key — that would
   mean the shipped JSON was not generated by the script it names, which is a finding in its own
   right and not something to work around.

3. **`docs/qcd-background-audit/REFERENCE-FIXTURE.md` — the map.** One table, and it is the
   deliverable the next four prompts actually consume. For **every** assertion in the test tree
   that depends on a QCD background number, one row: test module, test name, what it asserts,
   the asserted tolerance, the value it achieves today, and **whether it is scored against the JSON,
   against another part of the tree, or against a closed form**. Start from

   ```bash
   grep -rln --include="*.py" "QCD\|qcd" ComputeTargets/tests/ CosmologyModels/tests/ LiouvilleGreen/tests/
   ```

   which finds eleven modules on this tree (`test_background_tau.py`,
   `test_background_cs_tau_friction.py`, `test_background_derivatives.py`, `test_gk_wkb_phase.py`,
   `test_tk_wkb_phase.py`, `test_phase_residual.py`, `test_residual_table_reuse.py`,
   `test_omega_eff_split.py`, `test_numeric_break_points.py`, `test_numeric_break_point_key.py`,
   `test_wkb_reference.py`) — **verify that list rather than trusting it**, and include
   `CosmologyModels/tests/` and prompt 01's new module.

   Each row must also say **which kind of change would move it**: a `T(z)` node value, the
   representation's shape, the break-point set, or none of the three. That classification is what
   lets prompt 04 know that it has to re-score six tests and not eleven.

4. **Record the two floor issues.** `[02-qcd-reference-floor]` says the QCD $\tau$/$\tau_s$
   references are themselves good only to 1.9e-14 relative, and
   `[03-qcd-short-baseline-reference-endpoint-rounding]` says the short baselines carry up to
   ~1e-13 from rounded `log1p(z)` endpoints. Both are **re-measured, not closed, here**: quote
   what the regenerator reports for each in `REFERENCE-FIXTURE.md`, and note that prompt 06 is
   where they may change, because after it the reference stops being circular.
